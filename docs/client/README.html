LumenStage Previz v1

Live 3D previz and DMX monitor for the Prodigy 12 show — it listens to the lighting network and displays what the console is playing. The app never transmits anything: zero risk for the show.

Start (Mac)

  1. Unzip the archive anywhere (Desktop, Documents…).
  2. Right-click Start-LumenStage.command → Open → Open (needed the first time only).
  3. If macOS asks to allow node to accept incoming network connections: Allow.
  4. Your browser opens at http://localhost:4480 — the 3D previz. Drag to orbit, keys 1/2/3 for preset views, Monitor tab for raw DMX.

Seeing “Node.js 20 or newer is required”? Install the LTS version from nodejs.org (takes 2 minutes, once), then launch the file again.

Start (Windows)

Double-click Start-LumenStage.bat. Same flow.

Try it without the console

Also double-click Start-FakeShow.command (or .bat): it simulates the console and plays a test show. Both pixel walls animate in the 3D view.

With the real console

  1. Connect the computer to the lighting network (Ethernet) and set its IP as instructed by the lighting operator.
  2. As soon as Art-Net for universes 1–4 (the Tambora battens) reaches this computer, the previz animates by itself.

Heads-up for the operator: if the console sends Art-Net as unicast to the nodes only, this computer will not see it. Either enable broadcast for universes 1–4, or add this computer's IP as an extra unicast destination on the console. The app only listens — it never replies or transmits.

Troubleshooting

  • NO SIGNAL: check the network cable, the IP settings, and that the console actually outputs universes 1–4 towards this machine (see the note above).
  • The page does not open: browse to http://localhost:4480 manually.
  • “UDP 6454 unavailable”: another Art-Net application is running on this machine — close it and relaunch.

Stop

Close the Terminal window (or Ctrl+C inside it).
