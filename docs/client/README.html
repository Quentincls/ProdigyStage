LumenStage

A live 3D copy of the Prodigy 12 light show, on your screen.

Safe by default: out of the box this app only listens to the lighting network — no address is configured, so it physically cannot send anything and you cannot break the show with it. It only ever transmits after you deliberately set it up with the lighting operator, which is Part 4 below.

Part 1 — Install and open it (5 minutes, at home)

You only do this once. You need a computer and an internet browser.

Mac or Windows? The folder contains both. Every file starting with Mac- is for macOS, every file starting with Windows- is for Windows. Use your half and ignore the other. The steps below are written for Mac; on Windows it is the same but simpler — a plain double-click on Windows-Start-LumenStage, no right-click needed.

  1. Unzip the file you received. Put the LumenStage folder anywhere (Desktop is fine). a folder containing a few files, including Mac-Start-LumenStage.
  2. Right-click (not double-click!) on Mac-Start-LumenStage, choose Open, then Open again in the warning popup. macOS asks this the first time only — afterwards a normal double-click works. a black Terminal window opens with a few lines of text. Leave it open — it IS the app. Closing it stops everything.
  3. If your Mac asks “Do you want the application node to accept incoming network connections?” → click Allow.
  4. Wait 2 seconds. your browser opens by itself on a dark screen: a 3D room with the message “Waiting for the console”. That's normal — nothing is connected yet.

Instead you got a message saying “Node.js 20 or newer is required”? That's a small free program the app needs. Go to nodejs.org, click the big green LTS download button, install it like any app (2 minutes, once), then go back to step 2.

Part 2 — See it working, without the console (2 minutes, at home)

The folder includes a fake lighting console, so you can see the app alive right away.

  1. Keep the app from Part 1 running.
  2. Right-click on Mac-Start-FakeShow → Open → Open (first time only). a second Terminal window with a line of numbers updating every second.
  3. Go back to your browser. the two light walls in the 3D room are now animating — rainbows, waves, chases — and the top bar says “Console connected” with a green dot. A time counter runs at the bottom left.
  4. Play around: drag the mouse to turn around the room, scroll to zoom, press keys 1, 2, 3 for ready-made camera angles.
  5. Done playing? Close both Terminal windows. That's how you quit.

Part 2b — Building a show from the music (optional, at home)

Compose listens to the track and proposes a first light show. You say what each part should feel like; it does the timing.

  1. Put the show's audio, as a .wav file, into the data/music folder — it sits next to Mac-Start-LumenStage, inside data. The folder is created the first time you start the app, and there is a text note inside it. the file is only read. It is never modified, and never sent anywhere.
  2. In the app, click Compose at the top, then pick the track. after a few seconds, the whole track appears as a waveform cut into chapters — Intro, Build, Drop, Break…
  3. Click a chapter, then choose what it should feel like: a palette, a mood, how much energy, how much movement. the 3D room changes immediately, and the light moves in time with the music.
  4. Happy with it? Send to Edit. It becomes a normal show you can adjust scene by scene.

Where the music changes is measured. Which colour goes where is our suggestion — change anything you disagree with, that is the point.

Telling it what the show is about

At the top of the panel on the right there is a line marked Direction. Click it and describe the show in your own words — the story, the places it goes, the colours you already have in mind:

“A narrative show. It opens in a cold cave, blue and almost still. After the first drop it breaks into a red, aggressive world. The last ten minutes are white and euphoric.”

Press Propose a direction and every chapter gets a name and a feel from what you wrote — “Cave”, “First light”, “Red world” — instead of “Intro 1, Build 2”. Everything it proposes is still yours to change afterwards, chapter by chapter, exactly as before.

This one step needs the internet, and a key we give you: open Direction, paste the key, press Save the key. It is stored on this machine only. Without it, Compose works exactly as described above — you just choose the colours yourself.

Part 3 — At the venue, with the real show

Do this together with the lighting operator. Allow 15 minutes the first time.

  1. Connect the Mac to the lighting network with an Ethernet cable (ask the operator which socket/switch).
  2. Ask the operator what IP address to give the Mac, and set it in System Settings → Network → your Ethernet connection.
  3. Start the app (Mac-Start-LumenStage, like in Part 1). Show the operator the orange note below.
  4. Ask the console to play anything on the light walls (the Tambora bars). the 3D walls light up and move exactly like the real room, and the top bar turns green: “Console connected”. If the console sends its timecode, the counter bottom-left runs in sync with the show.
  5. The most useful thing you can do: record a full run of the show. Click the gear ⚙ (top right) → Runs → ● Record a run before the show starts, and stop it at the end. This creates a file in the LumenStage/data/recordings folder — send us that file: it lets us build and test everything else on the real show, without the console.
  6. If the colors on screen don't match the room (say, red on stage but blue on screen): film 10 seconds showing both the room and the screen, and send us the video. It's a 5-minute remote fix on our side.

Show this to the lighting operator: the console must actually send Art-Net for universes 1–4 towards this computer. If the console only sends unicast to the DMX nodes, this Mac will see nothing. Either enable broadcast for universes 1–4, or add this Mac's IP as an extra unicast destination. Two-minute change, fully reversible, the rig keeps receiving normally. At this stage the app listens only — it has no address to send to, so it cannot transmit.

Part 4 — Changing the show for real (the commissioning session)

Do this with the lighting operator, in a rehearsal. Allow an hour the first time. Nothing here is permanent — everything goes back to normal in two minutes at the end.

What we are about to do. Today the console talks straight to the lights. We are going to put this computer in the middle, so that at the moments you choose it can say “this bar isn’t red any more, it’s blue, and it pulses” — and the room obeys. Everywhere else the console keeps running its show exactly as before.

NowConsole → lights
During the sessionConsole → this computer → lights
After the sessionConsole → lights (put back)

Show this to the lighting operator — this is the one thing that must happen first. For universes 1–4, the console must stop sending to the lighting nodes and send only to this computer’s IP address instead. If the console keeps reaching the lights directly while we are also sending, two sources fight over the same fixtures and you get flicker. This is a two-minute change on the console, and it is fully reversible.

Step 1 — Cable and addresses

  1. Connect the computer to the lighting network with an Ethernet cable, and set the IP address the operator gives you.
  2. Ask the operator for two things and write them down: the computer’s IP (which they will point the console at) and the address to send the lights to (the node’s IP, or a broadcast address).
  3. Start the app. Update it first if we have told you to.

Step 2 — Tell the app where the lights are

  1. Gear ⚙ → Live output → Advanced.
  2. Type the lights’ address in Lighting network address and press Save. the panel stops saying it cannot send, and a Connect to the lights button appears.

Until this address is filled in, the app physically cannot send anything, whatever you click. That is why it has been safe to explore until now.

Step 3 — Step into the chain, and check nothing changed

  1. Ask the operator to make the console send universes 1–4 to this computer only (the orange note above).
  2. Click Connect to the lights. the room looks exactly as it did a second ago. The app is now passing the console through, untouched.
  3. Watch the room for two full minutes. Any flicker, any colour that hops, anything at all different → click Disconnect and tell us. Do not go further.

Step 4 — Go live

  1. Press and hold the Hold to go live button for a second. the bar at the top turns red and reads “LIVE — your scenes are playing on the lights”.
  2. Nothing changes in the room yet — you have no scene at this moment of the show. That is normal and it is a good sign.

Step 5 — Change a passage

  1. Switch to Edit. Pick a short passage the operator can replay easily.
  2. Go to that moment: click its section in the bar above the timeline, or drag the playhead.
  3. + Scene, then set Start and End to cover the passage.
  4. Change → pick a look. For a first test use something unmistakable: Deep red, Full white. For something that blinks: Pulse, Heartbeat, Storm.
  5. Ask the operator to replay that passage. when the console’s timecode enters your scene, the walls take your colour over half a second, hold it, and hand it back to the console at the end.

A scene fires on the show’s timecode, so the console has to be playing that passage. The Preview button in the panel only shows the scene on your screen — the real lights always follow the console’s clock, never the editor. This is deliberate: it means nobody can change the room by scrubbing around during a show.

If anything looks wrong

What you seeWhat to do
Flicker, or colours fighting each otherThe console is still reaching the lights directly. Disconnect, and have the operator finish the reroute.
The room went dark when you connectedThe address is wrong, or the console is no longer reaching this computer. Disconnect — the operator can put the console back in one move.
Your scene plays at the wrong momentCheck its Start and End against the show’s timecode, not the clock on the wall.
Your scene never playsThe console must be playing that part of the show, and the top bar must read LIVE.
Anything you don’t like, at any timeBLACKOUT (one click, top of the screen) kills everything. Stop playing my scenes gives the show back to the console. Disconnect takes this computer out of the chain.

Step 6 — Putting everything back

At the end of the session, unless we have agreed otherwise:

  1. Click Stop playing my scenes, then Disconnect.
  2. Ask the operator to point the console back at the lighting nodes. the console runs the show on its own again, exactly as before we arrived.
  3. You can close the app. Your scenes are saved and will still be there next time.

Worth knowing before a performance. While this computer sits in the chain, the show goes through it. If it crashes, sleeps or gets unplugged, the lights stop — the software gives control back within a quarter of a second if it fails, but it cannot deliver the console’s signal if the machine is off. That is an acceptable trade in a rehearsal. Before using this in front of an audience, talk to us.

Please record the session. Gear ⚙ → Runs → ● Record a run, from the start. If anything behaves oddly we can replay exactly what happened instead of guessing from a description — that is how every problem so far got fixed in one round.

Updating (10 seconds, whenever we tell you)

We improve the app remotely. When we say "there's a new version", do this:

  1. Close LumenStage if it's running (close the Terminal windows).
  2. Double-click Mac-Update-LumenStage (right-click → Open the first time, like in Part 1). a Terminal window downloads the new version, then prints "Update complete." with the build date.
  3. Start the app again. That's it.

Updating never touches your work: scenes, presets, recordings and fixture placements all stay exactly as they were. It needs an internet connection.
