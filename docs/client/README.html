LumenStage Previz v3

Live 3D previz and DMX monitor for the Prodigy 12 show — it listens to the lighting network and shows what the console is playing. The app never transmits anything: zero risk for the show.

New in v3: the app opens in Watch — just the 3D room and the timecode. Edit lets you create scenes on the timeline (pick an effect, a color, done — they show in the previz only). The gear menu (top right) holds the technical tools: DMX monitor, placement, and Runs — press Record there while the show plays, replay it anytime without the console.

Step 1 — First launch (Mac)

  1. Unzip the archive anywhere (Desktop, Documents…). a LumenStage folder.
  2. Right-click Start-LumenStage.command → Open → Open. This right-click dance is needed the first time only; afterwards a normal double-click works. a Terminal window opens with a few log lines.
  3. If macOS asks whether node may accept incoming network connections → Allow.
  4. Wait 2 seconds. your browser opens on a dark screen titled “LumenStage Previz — waiting for the console”. That's the 3D room.

Instead you see “Node.js 20 or newer is required”? Install the LTS version from nodejs.org (2 minutes, one time only), then relaunch the file from step 2.

On Windows: same flow with Start-LumenStage.bat, plain double-click.

Step 2 — Play the test show (no console needed)

  1. Keep the LumenStage window from step 1 running.
  2. Right-click Start-FakeShow.command → Open → Open (first time only — it simulates the console). a second Terminal window printing “u1 40 pkt/s | u2 40 pkt/s…” every second.
  3. Go back to the browser. the two pixel walls animate in 3D (rainbow, waves, chases) and the top bar turns green: “Listening on universes 1–4 — 160 pkt/s”.
  4. Play with it: drag to orbit, wheel to zoom, keys 1 / 2 / 3 for Face / Top / Tribune views, Monitor tab for the raw DMX values.
  5. To stop: close both Terminal windows.

Step 3 — At the venue, with the real show

Do this together with the lighting operator. Reminder: the app only listens — it never sends anything to the rig.

  1. Connect the Mac to the lighting network with an Ethernet cable.
  2. Ask the operator which IP address to use, and set it in System Settings → Network.
  3. Launch Start-LumenStage.command (step 1).
  4. Ask the operator to make sure Art-Net universes 1–4 actually reach this computer — see the note below.
  5. Have the console play anything on the Tambora battens. the previz animates, and the top bar shows “Listening on universes 1–4 — … pkt/s from <console IP>”.
  6. Compare the room and the screen. If the colors don't match (e.g. red on stage shows as blue on screen), film a few seconds showing both — the fixture color map can then be fixed remotely in minutes.

For the lighting operator: if the console outputs Art-Net as unicast to the nodes only, this computer will never see it. Either enable broadcast for universes 1–4, or add this computer's IP as an extra unicast destination on the console. Two-minute change, fully reversible, the rig keeps receiving normally.

Troubleshooting

  • “NO SIGNAL” with the fake show running: make sure both Terminal windows are still open; close everything and redo steps 1–2.
  • “NO SIGNAL” at the venue while the console plays: check the cable and IP, then the operator note above. Still nothing? Tell us — it may be a universe numbering detail we can fix remotely.
  • The browser page did not open: browse to http://localhost:4480 manually.
  • “UDP 6454 unavailable”: another Art-Net app is running on this machine — close it and relaunch.

Stopping

Close the Terminal window(s), or press Ctrl+C inside them. Nothing keeps running in the background.
